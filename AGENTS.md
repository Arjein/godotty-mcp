# Godotty (`godotty-mcp`) — agent guide

MCP server + Godot editor plugin + runtime helper that let AI agents edit, **run, see, play-test
and debug** Godot 4 projects. Full plan and milestones: `docs/PLAN.md`. Decisions: `DECISIONS.md`.
Known problems: `FLAGS.md`.

## Layout

- `server/` — the MCP server (TypeScript, Node 20+, ESM, stdio). npm workspace package.
  - `src/index.ts` stdio entry (disposes services on stdin close/SIGTERM) · `src/server.ts` builds
    the `McpServer` (transport-agnostic) · `src/services.ts` wires long-lived services (Godot
    executable, `GameManager`, `ScriptChecker`) · `src/config.ts` CLI flags/env.
  - `src/tools/` one file per tool or tool group; each exports `defineTool(...)` objects, listed in
    `src/tools/index.ts`. `registry.ts` wraps handlers so errors become MCP `isError` results.
  - `src/godot/` everything that knows Godot: `executable.ts` (spawn/exec, version ≥ 4.5),
    `variant.ts` + `section-file.ts` (text formats of project.godot/.tscn/.tres),
    `project-file.ts`, `scene-file.ts` (parse + render tree), `godot-log.ts` (stderr blocks and
    Logger records → `GodotError`), `game.ts` (one game process at a time, output buffer,
    errors), `runtime-injection.ts` (temporary `override.cfg` autoload), `lsp-client.ts` +
    `script-checker.ts` (editor LSP → headless editor LSP → `--check-only`), `input-names.ts`
    (generated by `scripts/gen-input-names.py`; don't edit).
  - `src/godot/docs/` `godot_docs` backend: `class-xml.ts` (class reference XML → signatures +
    raw description text; descriptions keyed by `memberKey`, overloads get `#n`), `docs-store.ts`
    (signature index from `--doctool`, cached per Godot build in
    `~/.cache/godotty-mcp/docs/<build>-v<CACHE_FORMAT>/`; description text fetched per class from
    the engine source at the release tag or build commit, cached), `lookup.ts` (class / member via
    ancestry / enum / ranked search), `bbcode.ts` (doc markup → Markdown, GDScript examples only).
    Bump `CACHE_FORMAT` whenever the cached JSON shape changes.
  - `src/godot/tests/` `run_tests` backend: `test-runner.ts` (detect GUT/gdUnit4 by CLI entry
    script, always `--import` first, run with the verified flags, collect parse errors of test
    scripts) and `junit.ts` (both frameworks' JUnit dialects → `TestSuite`/`TestCase`).
  - `src/bridge/` TCP bridge to Godot: `protocol.ts` (the single source for messages, methods and
    `PROTOCOL_VERSION`; one JSON object per line), `bridge-server.ts` (loopback listener, token
    hello, request/response with timeouts), `runtime-client.ts` (calls into the running game,
    maps remote error codes to actionable `ToolError`s). The GDScript side mirrors `protocol.ts`.
  - `src/util/` `errors.ts` (ToolError + codes), `sandbox.ts` (path resolution), `paginate.ts`.
  - `test/` Vitest unit tests mirror `src/`; `test/integration/` runs real Godot (excluded from
    `npm test`).
- `addon/addons/godotty_mcp/` — GDScript editor plugin + runtime helper (`runtime/`). The server
  copies `runtime/*.gd` into `<project>/.godot/godotty_mcp/runtime/` at each launch; the helper is
  inert unless started with `-- --godotty-events=<file>` and writes JSON lines there (`ready`,
  `error`). With `--godotty-port=<port>` plus the `GODOTTY_BRIDGE_TOKEN` env var (never argv) it
  connects to the bridge: `godotty_bridge_client.gd` (TCP + dispatch), `godotty_commands.gd`
  (screenshot, wait, tree, get/set props), `godotty_input.gd` (input simulation). Its GUT tests are
  in `addon/tests/` (not shipped) and run via `test/integration/addon.test.ts`.
- `examples/demo-project/` — small Godot 4 3D project (GL Compatibility renderer, so it renders under
  Mesa/xvfb on CI) for demos and integration tests. Its GUT tests (`test/unit/`) need GUT:
  `scripts/fetch-test-addons.sh gut examples/demo-project` (addons/gut is gitignored).
- `scripts/fetch-test-addons.sh <gut|gdunit4> <project> [minor]` installs pinned, SHA-256-checked
  test frameworks (GUT release chosen per Godot minor); `scripts/gen-input-names.py` regenerates
  `input-names.ts`.

## Commands (run from repo root)

- `npm run lint` — ESLint (strict type-checked) + Prettier check + gdlint + gdformat check (GDScript
  lint covers `addon/` and the demo's `scripts/` and `test/` only, never third-party addons).
  gdtoolkit is installed via `pipx install 'gdtoolkit==4.*'` (binaries in `~/.local/bin`).
- `npm run typecheck` · `npm test` · `npm run coverage` (thresholds in `server/vitest.config.ts`).
- `GODOT_PATH=/opt/homebrew/bin/godot npm run test:integration` — real Godot against a temp copy
  of the demo project (fixtures are written by the test, so the demo project stays clean). CI runs
  it on Linux with Godot 4.5.2 and 4.7.2 (SHA512-verified downloads).
- `npm run format` — Prettier + gdformat write.
- Godot sanity check: `godot --headless --path examples/demo-project --quit-after 60`.

## Conventions

- TypeScript strict + `noUncheckedIndexedAccess`; no `any`; no magic numbers (named constants).
  TypeScript is pinned to 6.0.x because typescript-eslint does not support 7.x yet.
- Tool rules: precise description, zod input schema, compact structured output; lists paginate via
  `util/paginate.ts`; expected failures throw `ToolError(code, message, hint)` — the hint says what
  to do next. Never print to stdout outside the MCP transport (stdout is the protocol channel).
- Every user-supplied path goes through `ProjectSandbox.resolve` (accepts `res://`, relative,
  absolute; resolves symlinks; rejects anything outside the project root).
- Opt-in tools use `enabled: (config) => ...` and stay unregistered by default (`eval_gdscript`).
- GDScript: static types everywhere, `##` doc comments on public classes/methods, gdlint/gdformat
  clean. Indent with tabs.
- Verify Godot CLI flags/APIs against the installed version (`godot --help`, `--doctool`, a real
  run) before relying on them. Dev machine: Godot 4.7.2 at `/opt/homebrew/bin/godot`. Minimum
  supported: 4.5.
- Commit `*.uid` files Godot generates next to scripts; never commit `.godot/`.
- Copy the demo project in tests with `copyDemoProject` (skips `.godot` and locally installed test
  addons); integration tests install frameworks with `installTestAddon`.
- `test/helpers/fake-runtime.ts` plays the runtime helper over real TCP for bridge/tool tests.
- Integration tests open real game windows for screenshots (CI: Xvfb + Mesa llvmpipe).
- Tests fake Godot with `test/helpers/fake-godot.ts` (scripted processes) and
  `test/helpers/fake-lsp.ts` (TCP language server); tool tests go through a real MCP client
  (`test/helpers/tool-client.ts`).
- Godot facts this code relies on (exit codes, LSP handshake, Logger, override.cfg, doctool):
  `docs/agents/godot-behavior.md`. Read it before touching `src/godot/`.
- fast-xml-parser refuses elements named `constructor` (prototype-pollution guard); `class-xml.ts`
  renames them to `ctor` before parsing — keep that when touching XML parsing (JUnit in M4 too).
- The only network access is `godot_docs` fetching class XML from raw.githubusercontent.com
  (URL contains only the Godot version and class name); `--offline` / `GODOTTY_OFFLINE=1` turns it
  off. Never add other network calls without an equivalent switch.
- Every bug fix gets a regression test.
